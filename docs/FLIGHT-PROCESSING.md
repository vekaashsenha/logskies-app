# Local flight processing

Open `/dashboard`, set your company name/logo, register your batteries and optionally record a preflight. In Flight logs, select the source aircraft and import a `.bin` or `.tlog` (50 MB maximum). Processing runs in a browser worker. Originals are stored once by SHA-256; repeated imports are rejected. Browser data clearing removes this history; export and retain your originals/evidence backups.

The parser reads DataFlash FMT definitions and supported ARM/EV, GPS/POS, BAT/BAT2 and cell records. MAVLink v1/v2 uses CRC-extra validation for heartbeat, system status/time, GPS/global position, battery status and extended system state. It supports timestamped tlog capture and selects one aircraft system. Signed packet cryptographic signatures are not authenticated. Unknown records are skipped with warnings; truncated files and missing timestamps remain visibly incomplete. A log beginning armed without a preceding disarmed heartbeat cannot establish a complete MAVLink interval.

Arming intervals are proxies, not verified takeoff/landing. Review timestamps, locations and actual drone UIN. Physical battery identity cannot be inferred from telemetry. Unique unused preflights within a nonnegative interval under 30 minutes can match; ambiguous/incomplete cases require manual selection. Multiple battery channels remain separate.

Health uses 40% capacity, 35% sag and 25% cycles only when all inputs qualify. Partial-flight capacity is not full capacity health. Capacity requires operator-confirmed comparable discharge to cutoff and expected delivered mAh. Sag requires at least three current steps exceeding 2C within two seconds, positive voltage drop, baseline resistance and comparable temperature/state of charge. Dynamic resistance uses delta voltage / delta current. Sag penalties begin above a 30% baseline increase, then fall by 100 points per further unit of relative increase. Missing inputs produce Unassessed. Cycle counts are supplied by the operator and never incremented by scans.

Reports include company logo, source hash/parser/model versions, telemetry observations, operator declarations and pass/fail/pending checks. Relative altitude is separate from verified AGL. The operator supplies measured AGL and applicable 60/120 m ceiling. RPC date checks do not authenticate certificates. Permission references do not authenticate permissions.

Regional GeoJSON accepts up to 200 Polygon/MultiPolygon features with WGS84 coordinates and `properties.zone` green/yellow/red. Source/publication metadata is retained. Segment intersection detects crossings between position samples; gaps over five seconds or uncovered geometry remain unknown. Antimeridian geometry is rejected. This is a horizontal geometry check: official map authenticity, vertical limits, temporary restrictions and actual route between samples still require review. No official airspace feed is integrated.

Official eGCA export acceptance always remains pending. These are draft evidence packs, not an assertion of DGCA approval or airworthiness. The precise official submission schema must be confirmed before a production compliance claim.

## Validation and provenance

`npm test` runs domain, telemetry/health/airspace and migration security tests. Synthetic `.bin` and `.tlog` fixtures are generated independently by `scripts/log-fixtures.mjs`; they are test data, not real flights. The independent 101,888-byte DataFlash fixture comes from [ArduPilot autotest](https://autotest.ardupilot.org/ArduCopter-AHRSAutoTrim-00000322.BIN); it lacks GPS/arming evidence, which stays unknown. Independent customer tlogs still need validation.

MAVLink subset schemas are generated by `scripts/mavlink-schema.mjs` from the included common/standard/minimal XML definitions obtained from the official [MAVLink repository](https://github.com/mavlink/mavlink/tree/master/message_definitions/v1.0). Definitions retain upstream licensing notices. Wire references: [MAVLink serialization](https://mavlink.io/en/guide/serialization.html), [ArduPilot log messages](https://ardupilot.org/copter/docs/logmessages.html).

`scripts/security.test.mjs` runs the actual migration in PGlite PostgreSQL with test auth/storage scaffolding. It tests tenant reads, pilot/admin writes, cross-organization foreign keys and storage access. PGlite's built-in UUID support replaces the pgcrypto extension declaration. This does not validate hosted Supabase JWT/session behavior or Storage HTTP endpoints.

The latest network dependency audit reports 32 advisories (22 high, 10 moderate), primarily inherited Expo/Metro/development tooling, including upstream braces/node-forge advisories without an available audit fix. See `npm-audit-current.json`. A forced audit fix proposes incompatible SDK downgrades; it was not applied. Resolve release dependency exposure before production deployment.
